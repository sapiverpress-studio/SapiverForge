Phase 1 · Day 24 · Automation Boundaries

Choosing what to automate

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
Do not automate a whole workflow simply because AI can participate in it. Break the work into decisions and actions, then choose the right control for each step: deterministic software for fixed rules, AI for ambiguity, and human control where consequence, uncertainty or accountability is high.

1. Automation should begin with the workflow, not the tool

The wrong starting question is “Where can I put AI?”.

The better question is “Which parts of this workflow are repetitive, which require judgement, which carry risk, and which should remain human decisions?”.

This avoids adding AI to steps that ordinary software already handles better.

2. Split the workflow into decisions and actions

A workflow often looks like one task but contains several different operations.

For example, handling a refund might include reading the request, checking the order, interpreting the reason, applying policy, approving the decision and issuing payment.

Each step can use a different control instead of forcing the entire process into one automated agent.

3. Fixed rules belong in deterministic software

If a condition can be expressed clearly and tested exactly, ordinary code is usually the right choice.

Examples include checking whether a date is within 30 days, whether a required field is missing or whether a user has permission to perform an action.

Using a language model for these decisions adds variability without adding useful judgement.

4. AI is useful where meaning is ambiguous

AI becomes useful when the input is messy or the task requires interpretation.

Examples include classifying free-text requests, extracting information from inconsistent documents, summarising evidence or drafting a response.

The model should still operate inside defined boundaries and pass its output to validation or release controls.

5. Consequence changes the automation threshold

Two technically similar tasks can deserve very different levels of automation.

Automatically tagging an internal note has low consequence. Automatically sending money, publishing legal advice or deleting data has much higher consequence.

As consequence rises, stronger validation and human approval become more valuable.

6. Reversibility matters

An action that can be easily undone is safer to automate than one that is difficult or impossible to reverse.

Drafting an email is reversible because a person can edit or discard it. Sending the email to thousands of customers is much less reversible.

Separate preparation from execution whenever the execution step has greater consequence.

7. Human review should focus on meaningful decisions

Human-in-the-loop does not mean making a person approve every trivial step.

If reviewers see hundreds of low-value approvals, they may begin clicking through without careful judgement.

Automate predictable low-risk work and reserve human attention for ambiguity, exceptions and high-impact actions.

8. Use thresholds to route work

A workflow can route cases differently according to risk or uncertainty.

Low-risk cases might proceed automatically after deterministic checks. Medium-risk cases might require additional evidence. High-risk cases can pause for human approval.

This creates graduated control rather than an unrealistic choice between “fully manual” and “fully automated”.

9. Measure whether automation actually improves the workflow

An automated process is not better simply because it uses less human effort.

Measure error rates, handling time, rework, escalations, cost and user outcomes.

If automation creates more corrections or more risk than it removes, reduce the automation boundary rather than defending the original design.

Worked example: triaging customer complaints

A company receives free-text customer complaints through a web form.

Complaint arrives
Validate fields
AI classifies issue
Rules assign route
Human handles exceptions
Response released

Required fields and account permissions are checked deterministically. AI classifies the complaint because the language varies from customer to customer.

Rules then route normal delivery complaints to the correct team. Complaints involving safety, legal threats or uncertain classification are escalated to a person.

The response may be drafted automatically, but the final send step can use the release-gate logic from Day 23 when the case is sensitive.

Why this matters

Many failed AI projects automate too much instead of designing the right division of responsibility.

Good systems let deterministic code do predictable work, let AI handle ambiguity, and preserve human judgement where consequences justify it.

The goal is not maximum automation. The goal is the most reliable workflow with the least unnecessary effort.

Key terms

Automation boundaryThe point separating work performed automatically from work requiring another control or a person.
Deterministic stepA step whose outcome follows explicit rules and should be predictable.
Human-in-the-loopA design in which a person participates in selected decisions or approvals.
ExceptionA case that falls outside the normal automated path.
ReversibilityHow easily an action can be undone after execution.
Escalation thresholdA condition that routes a case to stronger review or human control.
RoutingDirecting a case to the appropriate workflow path based on rules or classification.
ReworkAdditional work required to correct or repeat an earlier result.
